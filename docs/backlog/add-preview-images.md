## Why

A link shared on LinkedIn or elsewhere shows a large preview only when
the page declares an image (`og:image`, required by the Open Graph
protocol). Without it the preview is small, with text only. The user
wants each indexed page to have its own image, and chose to make them
in a session of their own.

## Known from the start

- **No page has an image of its own:** the two Medium articles had one
  each, but both came from the vendor's documentation and became tables
  on the site (decided on 2026-11-03).
- **Any image will likely carry the logo or the site's name,** and the
  logo is still to be reviewed
  ([card](review-the-logo.md)); the user already has an idea for it, and
  leans towards making the images after the restyle.
- **`og:image` takes a full address,** built like the other full
  addresses from the site's address
  ([ADR-002](../adr/ADR-002-relative-paths-and-site-address-at-build.md)).
- **The other Open Graph tags come first**
  ([card](../wip/add-description-and-open-graph-tags.md)), so adding the
  image redoes none of them.
- **Visual work is shown before it is committed:** alternatives side by
  side, then the result on the real page.

## Questions

- How the images are made: files drawn by hand and kept up to date, or
  generated by the build from each page's title.
- What they show, and at which size (LinkedIn recommends 1200 × 627
  pixels).
- Whether the "page not found" needs one: it asks not to be indexed.
