# Take the measures from the configured fonts

- **Created:** 2026-11-17
- **Status:** Open

## Why

The user opened this card on 2026-11-17, while cutting the card
[measure the fonts again when they change](../wip/measure-the-fonts-again-when-they-change.md).

Two values of the build are measured on one font each, and do not
follow the configuration (`config/fonts.txt`), which gives each role
its font:

- the table widths are estimated from Literata's character widths
  (`src/literata_widths.rs`), generated by hand with
  `end2end/tools/measure-literata-widths.mjs`;
- Hack's advance, 1233/2048 of an em, is written by hand in
  `src/markdown.rs`, for the wrap toggle of the code blocks, and in
  `src/table_widths.rs`, for inline code in a table.

A change of font in the configuration leaves these values as they
are. The browser tests catch them only when the page goes wrong on a
case at the limit; to put them right, someone has to know where they
are, measure the new font and write the values again. The user wants
the measures taken from the font of each role, whatever it is, so a
change of font means running the measure again, not writing a value by
hand.

## What is known

- **Where the measures are taken.** Decided by the user on 2026-11-17,
  while cutting the card above: in the build, in the browser, as the
  script for Literata does today (a canvas in Chromium, one character
  at a time).
- **The stylesheet's comments** (`style/input.css`) name Literata or
  Hack where they explain a measure, and one gives a number, 0.602em,
  the width of the zero in Hack. They change together with the
  measures.
- **The logo font.** No width measured on it was found in the code
  (checked on 2026-11-17).
- **The build has no browser today.** The Rust build writes the site;
  Chromium is used only by the browser tests, after the build, and in
  the pipeline in Playwright's container (`scripts/playwright-version.sh`).
  Supposed, not checked in detail: measuring in the build changes the
  order of the build's steps, locally and in the pipeline.

## Questions to answer

The ones known when the card was written; there may be more.

- **How the build gets a browser**, locally and in the pipeline, and in
  which step the measures are taken, given that the browser tests run
  after the build.
- **Which measures each role needs.** The text needs a width per
  character, in regular and bold; the code needs one advance while its
  font has a fixed width. What happens if the code font chosen is
  proportional.
- **What becomes of the stylesheet's comments** that name the fonts
  and give their numbers: written so they no longer depend on the
  font, or written by the build.
