# Measure the fonts again when they change

- **Created:** 2026-11-16
- **Status:** In work

## Why

The user opened this card on 2026-11-16, while cutting the card
[link the fonts to the build](../done/2026-11-16_link-the-fonts-to-the-build.md),
and put it in Next, after the fonts page. On 2026-11-17 it became the
last card on the fonts before the style guide is published.

Some values of the build are measured on a font, and would not follow
a change of font made in the configuration:

- the table widths are estimated from Literata's character widths
  (`src/literata_widths.rs`), measured in Chromium by
  `end2end/tools/measure-literata-widths.mjs`;
- the wrap toggle of the code blocks shows from a threshold computed
  with Hack's advance, 1233/2048 of an em.

Comments of the stylesheet also name the fonts where they explain a
measure.

## What is known

Checked in the code on 2026-11-17. The configuration
(`config/fonts.txt`) says `text=literata`, `code=hack`,
`logo=ibm-vga-8x16`; the description of each font
(`config/fonts/<folder>.txt`) holds no measure, and nothing ties the
measured values below to the font the configuration names.

- **The table widths.** `src/literata_widths.rs` is generated by
  `end2end/tools/measure-literata-widths.mjs` and read by
  `src/table_widths.rs`, which also holds by hand Hack's advance,
  1233/2048 of an em, for inline code in a table.
- **The wrap toggle of the code blocks.** `src/markdown.rs` holds
  Hack's advance by hand (`CODE_ADVANCE_NUMERATOR`, 1233, over 2048).
- **The stylesheet's comments.** `style/input.css` names Literata or
  Hack where it explains a measure; one comment also gives a number,
  0.602em, the width of the zero in Hack.
- **The logo font.** No width measured on it was found in the code.
